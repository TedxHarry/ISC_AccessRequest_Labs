# AR-019 · Compare entitlement, profile and role requests

**Before you start:** AR-018. Use Olivia and remove each test assignment before beginning the next case.

## Run three cases

1. Create a results table with columns: requested type, object ID, reviewer, assignment shown in ISC, native groups and removal result.
2. Request VPN directly as Olivia. Approve as Priya. Record one entitlement request and its target membership. Remove that assignment and verify the reset.
3. Request `AP-Finance-Reporting`. Approve as Daniel. Record the profile and both target memberships. Remove the test assignment and recheck.
4. Request `ROLE-Finance-Analyst`. Approve as Daniel. Record the role, its two profiles and all three target memberships. Remove it and recheck.
5. Compare how the requested object controls the business description and review, even when VPN is a common underlying entitlement.
6. If ISC detects a profile from existing entitlements, record the displayed representation. Use the saved request ID to establish what was actually requested; a later Access display is not a substitute for request history.

**Check:** Your table distinguishes all three object types and the account-level results. Explain which object you would offer for a single technical permission, a business bundle and a job package.

**Reset:** No new Olivia business assignments remain. Retain the access model for later modules.
