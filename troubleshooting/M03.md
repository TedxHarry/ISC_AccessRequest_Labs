## Common problems

| What you see | First check | What proves recovery |
|---|---|---|
| The application card exists but has no usable profiles | Inspect profile associations and requestability using the ordinary requester | The application offers its intended enabled profiles to the test user |
| A profile is only partly fulfilled | Compare each entitlement's native group and operation result | Every required group is present, or the unresolved operation remains explicitly open |
| Access remains after a removal | Inspect assignment origin, remaining access paths and the removal operation | The intended assignment is removed and unrelated access is preserved |

## AR-020 · Manage the profiles offered by Finance Services

[Open the guided lab](../guided-labs/AR-020/README.md). Use that lab's people and objects. Numbered Section references below refer to its walkthrough. Preserve later legitimate accounts and assignments when revisiting an earlier lab.

### If the result differs

Work down this table in the same Olivia session. Record what you inspect before changing another setting.

| Observation | Inspect and correct |
|---|---|
| Application absent before Section 2 or after restoration | Finance Services Configuration: Enable for Users and both Request Center options; save and reopen |
| Application opens but a profile is missing | Access Profiles association list; add the existing correct-source profile, save and wait for refresh |
| Profile also missing from direct search | Its enabled/requestable state, source, Olivia's existing access and any existing access-request segments |
| Administrator sees an item but Olivia cannot | Actual signed-in username and requester-specific catalog; administrator visibility is not Olivia's result |
| Saved associations are correct but old choices remain | Wait for processing, refresh the requester page and recheck before making another configuration change |

Record the evidence you would inspect, the smallest correction, the repeat check and the state you would leave for the next lab.

<details>
<summary>Compare your diagnosis</summary>

This evidence points to missing associations. Use Section 4 to add the existing two profiles and save; wait for refresh, then verify both choices in Olivia's session. Do not rebuild profiles, relax global request settings or modify AD membership. Retain the three-state evidence and restored configuration.

</details>

## AR-021 · Deliver HR Services from a business requirement

[Open the guided lab](../guided-labs/AR-021/README.md). Use that lab's people and objects. Numbered Section references below refer to its walkthrough. Preserve later legitimate accounts and assignments when revisiting an earlier lab.

### If the result differs

If James or Elena cannot sign in, finish their registration/session checks before requesting. If both HR groups appear after Payroll approval, inspect the actual profile contents and other assignments; do not conceal the result by denying an unrelated request. If Elena sees no review, inspect Assignees for the exact request and the object's saved policy. Keep an incomplete operation visible until it is resolved.

### Diagnose this ticket

This is a supplied practice case. Write your diagnosis before opening the answer; keep it separate from failures you actually observe in the tenant.

> Payroll was approved and Benefits was denied, but both HR groups are present on James's AD account. The saved Payroll profile contains both GG-HR-PAYROLL and GG-HR-BENEFITS. The team proposes closing the Benefits denial as successful.

Record the evidence you would inspect, the smallest correction, the repeat check and the state you would leave for the next lab.

<details>
<summary>Compare your diagnosis</summary>

The denial did not grant Benefits; the approved Payroll bundle supplied it. Record the actual Payroll grant and both native operations. Remove the incorrect requested Payroll assignment through the documented review/removal flow while its contents still describe the grant, then verify both business groups are absent. Check other assignments before expecting removal. Correct Payroll to contain Payroll only, save/apply and verify the definition. Repeat the Payroll grant and native separation checks, then complete cleanup. Do not treat editing a profile definition as proof that previously granted access was revoked.

</details>
