# Try It Yourself: Configure approvals

Complete the guided labs first. Then attempt these variations without copying the walkthrough. Use the expandable answers after making your own prediction or diagnosis. You can explain your reasoning aloud; no journal or submission is required.

## Hands-on challenge: Predict the actual reviewer before opening the task

**Start with:** Henry and Harper have clean Production Support test access and correct manager data. Inspect the profile's currently accepted policy, including any retained workflow, form or date requirement.

**Your task:** Predict the first actual reviewer for a new Henry request and a new Harper request. Submit separate complete requests, compare Process/Assignees with your predictions, and have each actual assigned reviewer deny the correct request. If the prediction differs, identify the saved policy/input responsible before editing anything.

**You have succeeded when:** Each prediction can be compared with a specific fresh request, recipient and policy. Both requests end denied, neither recipient gains Support, and an old reviewer assignment is not used as proof of a new request's route.

<details>
<summary>Show a hint</summary>

A configured reviewer category and a resolved person are separate values. A retained native workflow can supersede the direct-review configuration you remember from an earlier lab.

</details>

**Finish:** Leave the accepted review configuration and both recipients' baseline access intact; resolve both diagnostic requests.

### Compare the recipient's manager on a profile request

1. Record AP-Finance-Reporting's current grant reviewer and the current request-on-behalf setting. Follow [AR-023](../guided-labs/M04/AR-023/README.md) to temporarily enable everyone-for-anyone if needed.
2. Open **Admin > Access Model > Access Profiles > AP-Finance-Reporting > Access Requests**. Replace only its grant reviewer with **Manager**, save and reopen. Keep removal review unchanged.
3. Verify Liam (`acme.e008`) has Manager Priya and has no Reporting or VPN membership. In Acme Olivia, open **Request Center**, choose the option to request for others, select Liam, and select **Request for These Identities**.
4. Find AP-Finance-Reporting under **Access Items > Access Profiles**. Add it with reason `AR-028 recipient manager`, review the recipient as Liam, and submit once.
5. Inspect the new request ID in Approval Management. Verify Priya receives it as Liam's manager, although Olivia's manager is Daniel. Deny it in Acme Priya and confirm no Reporting or VPN was added to Liam.
6. Restore the profile's original grant reviewer and the original request-on-behalf setting. Save and reopen both.

**Ticket:** The colleague expected Daniel because Olivia clicked Submit. Which two identity records and which request field establish why Priya was correct?

<details>
<summary>Compare your diagnosis</summary>

</details>
